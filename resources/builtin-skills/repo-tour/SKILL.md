# 代码库导读

给第一次进入仓库的人一份可行动的导览。所有结论都要从文件里确认，不要套模板。

## 1. 收集事实

- README、package.json / pyproject / Cargo.toml、锁文件、tsconfig、构建与 CI 配置。
- 顶层目录逐一看一眼，不要只凭名字猜测职责。
- 找入口：main / bin / server / index；找配置：env 示例、settings 文件。
- 有测试就确认测试命令与目录；有脚本就确认每个脚本实际做什么。

## 2. 输出结构

- **一句话概览**：这个项目是什么、给谁用。
- **技术栈与工具链**：语言、框架、包管理器、测试、lint、构建、发布。
- **目录地图**：每个顶层目录一句话职责；关键子目录再展开一层。
- **关键入口与主流程**：从入口到核心功能的一次完整调用链。
- **常用命令**：安装、开发、测试、构建——只写配置里真实存在的命令。
- **从这里开始改**：按常见任务给 3 条建议（加一个接口 / 修一个 bug / 加一个页面），各指向对应文件。
- **不确定项**：没找到证据的地方明确列出。

## 约束

- 命令必须能在仓库配置中找到依据。
- 控制篇幅，宁可少而准；需要展开时先问用户关注哪部分。
