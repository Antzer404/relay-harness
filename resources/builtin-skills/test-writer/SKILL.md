# 编写测试

## 1. 先读懂现状

- 找到实现文件、被测函数的导出面与调用方。
- 从 package.json / pyproject / Makefile 确认测试框架和命令；读 2–3 个邻近测试，沿用同样的目录、命名与 helper。
- 先运行最相关的单个测试文件，确认基线能跑通，而不是一上来跑全量。

## 2. 设计用例

- 主路径：输入 → 输出、状态变化、副作用。
- 边界：空值、0、上限、Unicode、Windows 路径。
- 失败路径：抛错、超时、损坏输入。
- 只 mock 外部边界（网络、时钟、文件系统），不要 mock 被测逻辑本身。

## 3. 编写与运行

- 新增测试放在与被测文件对应的测试目录，命名与现有风格一致。
- 先跑单个测试文件，再跑相关套件；有快照就检查快照内容，不要无条件更新。
- 失败时先判断是测试假设错还是实现有 bug。若确认是实现 bug，明确告诉用户，不要偷偷改实现来让测试变绿。

## 输出

- 新增或修改的测试文件列表。
- 覆盖的行为清单，每条一句话。
- 实际执行的命令与结果（通过数、耗时）。
- 仍然缺失或难以覆盖的部分。
